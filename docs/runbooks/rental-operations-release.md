# Выдача, продление и возврат аренды: релиз

## Что входит в релиз

- единые операции `HANDOVER`, `EXTENSION`, `RETURN` для сайта и личного Telegram-чата сотрудника;
- неизменяемая история договора, клиента и машины;
- пробег, топливо, способ выдачи, адрес, депозит, состояние и удержания;
- видео осмотра и фото приборной панели через карантин, ClamAV и приватное хранилище;
- постоянное предупреждение, если фиксацию пропустили с причиной;
- защищённый просмотр материалов только после повторной проверки роли и компании;
- ровная правая панель действий на компьютере и нижняя панель на телефоне.

## Обязательные переменные

Проверьте значения из `.env.example`: `DATABASE_URL`, `AUTH_SECRET`, `PRIVATE_STORAGE_ROOT`, `CLAMAV_HOST`, `CLAMAV_PORT`, `CLAMAV_TIMEOUT_MS`, `RENTAL_OPERATION_MEDIA_STALE_MINUTES`, `PILOT_BOT_SERVICE_TOKEN`, `PILOT_BOT_API_BASE_URL`. Секреты не должны находиться в Git или логах.

Каталог `PRIVATE_STORAGE_ROOT` должен принадлежать пользователю приложения, не обслуживаться веб-сервером как статический и сохраняться между перезапусками.

## Порядок развёртывания

1. Создайте резервную копию PostgreSQL и запишите текущий commit/image tag.
2. Разверните ClamAV и дождитесь успешного healthcheck.
3. Выполните forward-only миграции:

   ```bash
   npx prisma migrate deploy --schema src/database/prisma/schema.prisma
   ```

   В составе релиза должна примениться `20260821120000_add_rental_operations`.

4. Запустите приложение и Telegram-бот из одного проверенного commit.
5. Запускайте очистку зависших загрузок каждые пять минут одним экземпляром:

   ```bash
   npm run rental-operations:reconcile-media
   ```

6. Проверьте `/login`, `/rentals`, одну карточку клиента и одну карточку машины.

## Smoke-проверка

На тестовом договоре последовательно:

1. Подтвердите договор и выполните выдачу с коротким безопасным видео и фото приборки.
2. Убедитесь, что договор стал `ACTIVE`, а пробег/топливо/депозит появились в истории.
3. Откройте обе защищённые ссылки. После выхода из системы они не должны быть доступны.
4. Продлите договор и проверьте календарь/дату возврата.
5. Выполните возврат, проверьте итоговые пробег, топливо, состояние и депозит.
6. Повторите отдельную операцию через личный чат бота. В группе отправьте обычный текст — бот не должен отвечать.

## Мониторинг

Следите за количеством `RentalOperationMedia` в `PENDING`, `SCANNING`, `PROMOTED`, `ERROR` и `CLEANING`, возрастом старейшей записи и ошибками ClamAV/хранилища. Не выводите в метрики или логи имена файлов, адреса, ФИО, телефоны и содержимое материалов.

Если пользователь пропустил файлы, это нормальная завершённая операция только при заполненной причине. Такой договор должен показывать предупреждение, а не считаться полностью зафиксированным.

## Восстановление и откат

- Не откатывайте применённую миграцию удалением таблиц или enum. Откат приложения выполняется только на совместимый commit; исправления схемы выпускаются новой forward-миграцией.
- При сбое до подтверждения повторите тот же запрос/кнопку: идемпотентный ключ вернёт существующую операцию.
- При зависшей загрузке не удаляйте файлы вручную. Запустите reconciler и проверьте смену статуса по lease/claim token.
- При недоступном ClamAV остановите новые выдачи/возвраты с файлами либо используйте явный пропуск с реальной причиной; не помечайте непроверенный файл как `CLEAN`.
- При компрометации Telegram-токена перевыпустите его и `PILOT_BOT_SERVICE_TOKEN`, затем перезапустите бот.

## Известные эксплуатационные границы

- Веб-загрузка допускает видео до 150 МБ и использует ограниченный Server Action body size; на малом VPS не допускайте много одновременных больших загрузок.
- Telegram Bot API в этом релизе ограничивает видео операции до 20 МБ, фото — до 15 МБ.
- Живую проверку LibreOffice, ClamAV и Telegram нужно выполнять в целевом окружении, где доступны соответствующие сервисы.
