# Telegram-бот Pilot+: установка на VPS

## Перед установкой

1. Дождитесь статуса VPS «Активен» в Aéza и запишите публичный IPv4.
2. Сначала проверьте вход по ключу `ssh -i ~/.ssh/pilot_plus_aeza_ed25519 root@SERVER_IP`.
3. Смените пароль root, который ранее был отправлен в чат: `passwd`.
4. Только после успешного входа по ключу отключите `PasswordAuthentication` и повторно проверьте SSH в отдельном терминале.
5. Разрешите входящие подключения только SSH; бот использует исходящий HTTPS и не открывает порт.

## Установка

Установите Docker Engine и Compose plugin из официального репозитория Docker для Ubuntu. Клонируйте Pilot+ в `/opt/pilot-plus`. Создайте `/etc/pilot-plus-bot.env`:

```dotenv
TELEGRAM_BOT_TOKEN=
PILOT_API_BASE_URL=https://pilot.example.com
PILOT_BOT_SERVICE_TOKEN=
REDIS_URL=redis://redis:6379/1
PILOT_STAFF_CHAT_ID=
REQUEST_TIMEOUT_SECONDS=8
```

Не коммитьте этот файл. Установите права и запустите:

```bash
chmod 600 /etc/pilot-plus-bot.env
cd /opt/pilot-plus
sudo sh bot/deploy/install.sh
systemctl status pilot-plus-bot
docker compose -f bot/docker-compose.bot.yaml logs --tail=100 telegram-bot
```

Логи не должны содержать токены, документы, телефоны, адреса или паспортные данные.

## Автоматические сообщения и расписание

Отдельный cron на сервере бота не нужен: работающий `pilot-plus-bot` запрашивает очередь уведомлений каждые 5 секунд, а API Pilot+ атомарно создаёт задачи с ключами дедупликации.

- `08:00–08:14 Europe/Moscow` — создаётся одна утренняя сводка на компанию и дату. По понедельникам в неё добавляется отчёт за семь завершённых московских дней.
- Каждые 15 минут — проверяются сохранённые GPS-сигналы, события геозон и скорости, приближающиеся и просроченные возвраты. Один и тот же порог повторно не отправляется.
- Не чаще одного раза в 3 часа — атомарно резервируется и выполняется синхронизация штрафов. Новый штраф отправляется в рабочую группу и личный чат связанного сотрудника.
- Новая заявка и изменение её статуса отправляются сразу в рабочую группу и личный чат ответственного сотрудника.

Сводка не подменяет неизвестные данные нулями. Если последняя попытка синхронизации штрафов завершилась ошибкой, сообщение содержит «Штрафы не проверены (API недоступен)».

Пороги GPS:

- арендная машина: до 6 часов — норма; 6 часов — предупреждение; 24 часа — критическая проблема; 48 часов — риск угона или глушилки;
- свободная машина: до 48 часов — норма; после 48 часов — проверить АКБ, питание и SIM-карту трекера;
- возврат: напоминание за 2 часа; срочное уведомление через 2 часа после планового срока.

Для диагностики проверьте одновременно приложение и бот:

```bash
docker compose logs --tail=200 app
docker compose -f bot/docker-compose.bot.yaml logs --tail=200 telegram-bot
systemctl status pilot-plus-bot
```

В норме нет повторяющихся `notification_worker_failed`. Ошибка одного сборщика не блокирует выдачу уже готовых уведомлений. Состояние синхронизации штрафов проверяется на странице «Состояние системы» и по `FineIntegration.lastAttemptAt`, `lastSuccessAt`, `lastErrorCode` в PostgreSQL.

## Обновление и откат

Перед обновлением запишите текущий commit. Получите проверенный commit и перезапустите service. Для отката вернитесь на записанный commit и снова выполните `systemctl restart pilot-plus-bot`. Бизнес-данные находятся только в PostgreSQL Pilot+, Redis содержит временное FSM-состояние и не требует резервного копирования.

После компрометации перевыпустите BotFather token и `PILOT_BOT_SERVICE_TOKEN`, обновите `/etc/pilot-plus-bot.env`, затем перезапустите service.

## Операции аренды для сотрудников

Рабочая группа остаётся только каналом уведомлений: бот игнорирует обычные сообщения и не принимает в группе выдачу, возврат или продление. Операции выполняются только в личном чате привязанного сотрудника.

В личном чате откройте `Аренды`:

1. Для подтверждённого договора нажмите `Выдать`, укажите пробег, топливо, офис/подачу, адрес и депозит.
2. Для активного договора нажмите `Продлить` либо `Принять`.
3. При возврате укажите пробег, топливо, состояние машины и решение по депозиту.
4. При наличии приложите фото кузова и приборной панели. Видео не является обязательным условием закрытия аренды.
5. Файлы можно пропустить: отсутствие фото или видео не блокирует подтверждение возврата. Если файлы добавлены, дождитесь завершения их загрузки перед подтверждением.
6. После подтверждения операция появляется в договоре, карточке клиента и истории машины.

Если Telegram принял файлы, но Pilot+ временно недоступен, состояние формы остаётся в Redis и кнопку подтверждения можно нажать повторно. Идемпотентный ключ не создаст вторую выдачу или возврат.

После обновления проверьте в личном чате связанного сотрудника:

```text
/start
Аренды → выбрать договор → пройти выдачу/возврат
```

Затем убедитесь, что в карточке договора появились факты и защищённые ссылки на видео/фото, а в рабочей группе бот не отвечает на произвольный текст.
