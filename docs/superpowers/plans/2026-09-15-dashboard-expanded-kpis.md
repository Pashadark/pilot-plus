# Расширение KPI командного центра — план реализации

**Цель:** дополнить существующий блок KPI без изменения его визуального языка: разделить обслуживание на ТО, ремонт и мойку, а также показать количество договоров и клиентов.

**Ограничение:** существующие карточки, сетка, типографика, отступы, цвета и адаптивность сохраняются. В рабочем дереве уже есть пользовательские изменения; исходные файлы не коммитятся автоматически, если были изменены до начала этой задачи.

## Задача 1. Расширить контракт данных и серверный запрос

**Файлы:**

- Изменить: `src/modules/dashboard/overview-types.ts`
- Изменить: `src/modules/dashboard/server/queries.ts`
- Тест: `src/modules/dashboard/server/queries.test.ts`

1. Добавить в `DashboardKpiDto` поля `maintenanceVehicles`, `repairVehicles`, `washVehicles`, `contracts` и `clients`, сохранив `serviceVehicles` как совместимый агрегат.
2. Сначала дополнить серверные тесты ожиданиями tenant-scoped подсчёта клиентов и выборки типа/даты повреждения записи обслуживания.
3. Расширить `DashboardRepository` методом `clientCount`, подключить `prisma.client.count` и передать результат в источник нормализатора.
4. Добавить в выборку обслуживания `recordType` и `damageReportedAt`; включить активные статусы ремонта, чтобы уже начатое повреждение не исчезало из счётчика.
5. Запустить: `npx vitest run src/modules/dashboard/server/queries.test.ts`.

## Задача 2. Посчитать независимые показатели без двойного учёта

**Файлы:**

- Изменить: `src/modules/dashboard/normalizers.ts`
- Тест: `src/modules/dashboard/normalizers.test.ts`

1. Сначала добавить тест с отдельными автомобилями на ТО, в ремонте и на мойке, дублирующей записью одного автомобиля, договорами разных статусов и заданным числом клиентов.
2. Разделить активные записи на множества уникальных `vehicleId` для ТО, ремонта и мойки.
3. Сохранить объединённое множество `serviceVehicleIds` для расчёта доступности автомобиля без двойного учёта.
4. Посчитать договоры только в статусах `CONFIRMED`, `ACTIVE`, `COMPLETED`; исключить `DRAFT` и `CANCELLED`.
5. Передать в KPI tenant-scoped количество клиентов.
6. Запустить: `npx vitest run src/modules/dashboard/normalizers.test.ts`.

## Задача 3. Добавить карточки в существующий интерфейс

**Файлы:**

- Изменить: `src/modules/dashboard/CommandCenterKpis.tsx`
- Изменить: `src/modules/dashboard/CommandCenterDashboard.test.tsx`

1. Сначала расширить UI-тест проверками карточек «ТО», «Ремонт», «Мойка», «Договоры» и «Клиенты» и их ссылок.
2. В существующий массив карточек добавить новые элементы, используя тот же компонент `Card`, размеры, тона и структуру содержимого.
3. Сохранить порядок: погода, доход, депозиты, свободно, в аренде, ТО, ремонт, мойка, GPS, договоры, клиенты.
4. Ссылки: ТО/ремонт → `/maintenance?view=list`, мойка → `/wash`, договоры → `/rentals`, клиенты → `/clients`.
5. Запустить: `npx vitest run src/modules/dashboard/CommandCenterDashboard.test.tsx`.

## Задача 4. Финальная проверка

1. Запустить целевые тесты трёх изменённых областей.
2. Запустить `npm run typecheck`.
3. Запустить `npm run lint`.
4. Запустить `npm run build`.
5. Проверить `git diff` и убедиться, что затронуты только KPI командного центра и тесты, без перезаписи пользовательских изменений.
