# TG CAR → СУПА ПРО: приём заявок

**Goal:** Форма TG CAR создаёт NEW Lead в существующем разделе «Заявки», не договор и не бронь.

**Architecture:** Сервер TG CAR отправляет ограниченный JSON в защищённый серверный endpoint СУПА ПРО. Компания и действующий ответственный задаются конфигурацией получателя. Детали машины, дат, расчёта и согласия сохраняются в зашифрованном комментарии существующего Lead. Детерминированный id заявки обеспечивает повторы без дублей; несовпадающий payload с тем же ключом отклоняется. Изменение схемы не требуется.

**Constraints:** Работа локально; никакой записи по SSH в рабочую БД и никакого deployment. SMS/оплата не подключаются. Номер не подтверждён. Не создаются реальные тестовые клиенты. Секрет только server-side, endpoint закрыт без настройки. Внешний URL только HTTPS, HTTP разрешён лишь loopback.

## Acceptance
Подтверждение клиенту содержит только номер обращения; чужие данные не возвращаются. Source = TG CAR, comment явно сообщает «Телефон не подтверждён». В «Заявках» существующий UI отображает комментарий и источник. Нет записи Rental/Client. Отключённый получатель возвращает ошибку без ложного успеха. Производственное включение требует отдельной настройки и разрешения на deployment.
