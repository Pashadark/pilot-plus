# Авито помощник проката и контроль ответа

## Область
Расширить существующий официальный входящий Avito API автоматическим сбором четырёх полей, подбором автомобилей и напоминанием менеджеру. Пользователь разрешил ответы только по объявлениям аренды, не продажи. История до включения нового сценария не обрабатывается.

Автоответ возможен только при совпадении проверенного ID, владельца и актуального арендного назначения объявления. Новые/неизвестные/архивные объявления и сообщения без контекста не включаются автоматически. Нельзя классифицировать сообщение о продаже как аренду только по упоминанию автомобиля. При смене назначения разрешённого объявления ответы выключаются.

## Диалог
Без представления «Я помощник TG CAR». Собирать автомобиль (модель объявления — предложение, не окончательный выбор), даты и время начала/возврата, общий планируемый пробег в км, телефон. Спрашивать только недостающее, не дублировать уже указанные сведения. Первый запрос: «Здравствуйте! Какой автомобиль вас интересует? На какие даты и время нужна аренда? Какой общий пробег планируете за весь срок? Оставьте, пожалуйста, контактный телефон.»

Ответы ограничены сбором данных по аренде. Не давать произвольные советы, не запрашивать паспорт/карты/коды, не обещать бронь, скидку или цену без подтверждения. Вопросы вне сценария передавать менеджеру. Отправка только вслед за новым входящим сообщением; нет рассылки и повторных напоминаний клиенту без ответа. При ручном ответе менеджера помощник замолкает до явного возобновления.

## Заявка и подбор
Сохранять обращение сразу, собранные поля дополняют ту же заявку без дублей. После заполнения — понятная сводка и уведомление менеджеру. Локальный разбор, без передачи переписки внешней AI-модели. Неоднозначные даты/телефоны/модель уточняются, не угадываются.

Подбор в заявке идёт по реальным машинам компании и интервалу аренды с учётом активных/подтверждённых броней и недоступности. Если даты не определены, нет утверждения «свободна». Если модель из объявления отсутствует в системе, честный запрос менеджеру; не выдумывать автомобиль. Перед оформлением аренды повторно проверять доступность.

## Ожидание менеджера
15 минут после входящего без последующего человеческого исходящего → одно Telegram-напоминание на эпизод ожидания. Открытие заявки и сообщения помощника не считаются ответом менеджера и не сбрасывают таймер. Идентификаторы исходящих помощника сохраняются отдельно для различения. После человеческого ответа эпизод закрывается; новое входящее создаёт следующий. Пропущенные/неподтверждённые данные API не подменяются выводом «менеджер ответил».

## Надёжность
Постоянное состояние диалога и outbox исходящих. Проверка аккаунта, ID объявления, свежести события, отсутствия ручного ответа и отсутствия уже отправленного вопроса непосредственно перед отправкой. Неопределённый результат отправки не повторять вслепую: сверить чат, иначе передать менеджеру. Сохранять ограничения API, Retry-After, остановку при отзыве доступа, секреты вне кода. Отдельный выключатель автоответов; входящие заявки продолжают работать при выключении.

## Приёмка
Продажа/неизвестный ID/нет объявления → ноль автоответов. История → ноль автоответов. Повтор webhook → один вопрос. Ответ менеджера → помощник остановлен. Ответ бота/просмотр заявки → таймер не сброшен. Все четыре поля сохраняются без выдумывания. Занятая машина не предлагается свободной. Ошибка отправки/429/перезапуск не дают дублей. Сначала тестовый арендный диалог с владельцем, затем включение списка.

## Статус
Дополнение согласовано пользователем: понимать «сегодня/завтра» по Москве, спрашивать время и срок при их отсутствии; показывать отдельно свободные на запрос и ожидаемые после возврата. ACTIVE с просроченным endsAt не становится свободной автоматически. Плановый возврат не гарантирует выдачу: нужна приёмка и подготовка. Новая отправка — только ответ на входящее; существующий тестовый чат владельца допустим для контрольной проверки и явного возобновления после ручного ответа.
