# Авито → заявки СУПА ПРО

## Согласованный сценарий

Получать новые входящие обращения через официальный API Авито, создавать заявку с источником «Авито», дополнять её следующими сообщениями того же чата и уведомлять менеджера существующим Telegram-ботом. Ответы клиентам, автоматическая бронь, отправка документов, изменение объявлений и массовая рассылка исключены.

## Данные заявки

- Фирма и ответственное лицо задаются серверной конфигурацией, не входящим сообщением.
- Уникальный ключ: фирма + аккаунт Авито + чат; уникальный идентификатор сообщения защищает от повторной доставки.
- Имя собеседника, объявление, исходные сообщения и ссылка на чат доступны менеджеру.
- Телефон только из явно предоставленного клиентом номера. Без телефона заявка сохраняется с пустым зашифрованным значением и понятным отображением; нельзя подставлять фиктивный номер или связывать клиента по имени.
- Машина/модель, даты, длительность, бюджет, место подачи извлекаются из текста. Недостающие и противоречивые поля имеют пометку «Нужно уточнить». Выводы всегда доступны для исправления менеджером.
- Название объявления — контекст, а не доказательство выбора конкретного автомобиля: клиент мог запросить другую модель в сообщении.
- Первоначальный разбор выполняется локально по явным данным; передача переписки внешнему AI-сервису в эту версию не входит.

## Доставка и безопасность

После проверки актуального контракта API использовать официальные webhooks. Не заменять существующие подписки других CRM. Входящий callback не считается доверенным доказательством: принадлежность сообщения аккаунту и содержимое проверяются чтением через API. Входящие тела ограничены по размеру, проверяются схемой, ставятся в очередь. Секреты остаются на сервере; в логах только безопасные коды и идентификаторы внутренних задач.

Ответ 429 останавливает запросы на срок Retry-After; если заголовка нет — ограниченная увеличивающаяся задержка. Ошибки авторизации выключают обработку и сигнализируют администратору, не запускают цикл повторов. Никакого парсинга страниц, эмуляции браузера или обхода ограничений.

Один чат создаёт одну заявку; повторные сообщения не создают дубли и не сбрасывают установленный менеджером статус. Telegram-уведомление о новой заявке отправляется через существующую транзакционную очередь; обновление переписки не должно создавать лавину уведомлений.

## Границы запуска

По умолчанию обрабатываются только сообщения после включения интеграции. Историческая загрузка не выполняется без отдельного запроса. Сначала dry-run без записей, затем проверка одного тестового обращения, после этого постоянный приём. Нельзя обещать абсолютное отсутствие блокировки со стороны Авито.

## Проверки до публикации

Подделанный callback, чужой аккаунт/фирма, исходящее сообщение, дубликат, неизвестный тип сообщения, отсутствие телефона, конфликт дат, повтор после 429, отказ API, потеря доступа, одновременные сообщения и сохранение ручных изменений менеджера. Проверить заявку и ровно одно уведомление на реальном тестовом обращении. Сохранить предыдущий серверный релиз и возможность отключить интеграцию без потери заявок.

## Следующий технический этап

Получить актуальную схему webhook и требования доступа без обхода ограничения документации. Проверить существующие подписки. Добавить серверную конфигурацию, очередь входящих событий, обработчик, выделение полей и тесты, затем выполнить dry-run. Наличие API-ключа подтверждено; постоянный импорт ещё не реализован.
