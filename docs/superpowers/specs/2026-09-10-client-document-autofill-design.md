# Автозаполнение нового клиента по документам

## Цель

Ускорить создание клиента и не заставлять сотрудника вручную переписывать паспорт и водительское удостоверение. Распознавание помогает заполнить форму, но сотрудник всегда проверяет и при необходимости исправляет данные до сохранения.

## Сценарий

- В финальном блоке действий формы нового клиента рядом с кнопкой «Создать клиента» находится вторичная кнопка «Автозаполнение по документам».
- Кнопка открывает компактное окно с тремя отдельными обязательными для запуска распознавания слотами: основной разворот паспорта, страница с регистрацией и водительское удостоверение.
- После выбора файлов сотрудник нажимает «Распознать и заполнить».
- Во время обработки каждый слот показывает состояние загрузки, а общая кнопка блокируется и показывает прогресс.
- Распознанные значения подставляются в существующие поля формы: ФИО, дата рождения, паспортные реквизиты, кем и когда выдан, код подразделения, адрес регистрации, номер и сроки водительского удостоверения.
- Значения с отсутствующим или ненадёжным результатом не выдумываются и остаются пустыми. Уже введённое сотрудником значение не затирается пустым ответом.
- После распознавания форма переходит к разделу «Документы и данные», показывает уведомление о количестве заполненных полей и просит проверить результат.
- Три исходных изображения сохраняются в защищённом хранилище карточки после создания клиента: основной паспорт и регистрация как два паспортных документа, водительское удостоверение как документ ВУ.
- Ошибка одного изображения не отменяет удачные результаты других изображений. Пользователь видит понятную ошибку по конкретному файлу и может повторить попытку.

## Архитектура и данные

- Существующий локальный OCR-маршрут расширяется параметром типа документа: `PASSPORT_MAIN`, `PASSPORT_REGISTRATION`, `DRIVER_LICENSE`.
- Основной паспорт использует существующий разбор реквизитов; для регистрации и ВУ добавляются отдельные чистые парсеры с модульными тестами.
- Клиентская форма отправляет три изображения параллельно только после явного нажатия кнопки и объединяет непустые результаты.
- Распознавание выполняется локально на сервере через Tesseract. Паспортные изображения не отправляются во внешние сервисы и временные OCR-файлы удаляются после обработки.
- Механизм загрузки документов после создания клиента переиспользует существующее защищённое хранилище. Для страницы регистрации используется отдельный заголовок «Регистрация по паспорту» в категории паспорта.

## Интерфейс

- Новая кнопка визуально вторичная и не конкурирует с основной кнопкой создания.
- Окно доступно с клавиатуры, имеет явные подписи трёх документов, ограничения формата и размера, а также кнопку отмены.
- На мобильном экране кнопки и слоты располагаются в одну колонку без горизонтальной прокрутки.
- Статусы описываются текстом, а не только цветом.

## Ошибки и ограничения

- При неподдерживаемом формате или превышении лимита показывается toast с названием проблемного документа.
- Если OCR ничего не нашёл, форма остаётся доступной для ручного ввода.
- Автозаполнение не создаёт клиента автоматически и не меняет его статус.
- OCR не считается юридической проверкой документа; финальное подтверждение остаётся за сотрудником.

## Проверка

- Модульные тесты парсеров основного паспорта, регистрации и водительского удостоверения.
- Компонентный тест кнопки, окна из трёх загрузок, частично успешного результата и заполнения существующих полей.
- Тест маршрута на допустимые типы документа и отказ для неизвестного типа.
- Проверка создания клиента с сохранением всех трёх файлов.
- TypeScript, lint, production build и ручная проверка формы на мобильной и широкой ширине.
