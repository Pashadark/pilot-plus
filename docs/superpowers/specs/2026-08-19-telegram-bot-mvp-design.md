# Pilot+ Telegram Bot MVP — дизайн

**Дата:** 19 августа 2026 года  
**Статус:** утверждённое направление  
**Выбранный подход:** отдельный Python-бот, работающий только через защищённый Pilot+ API

## 1. Цель

Telegram-бот становится быстрым мобильным интерфейсом к Pilot+. Он не хранит собственные копии клиентов, машин, аренд, договоров или ТО и не подключается напрямую к PostgreSQL. Единственным источником истины остаётся backend Pilot+.

Первая версия обслуживает клиентов и сотрудников. Она должна сократить ручную работу с датами, исключить двойное бронирование и дать клиенту доступ к своим заявкам, арендам и документам.

## 2. Границы первой версии

В MVP входят:

- `/start` и безопасная привязка Telegram-пользователя;
- персональная одноразовая ссылка для привязки существующего клиента;
- привязка сотрудника с проверкой его активной роли в Pilot+;
- разные меню клиента, водителя, диспетчера и администратора;
- просмотр клиентом своих активных и прошлых аренд;
- просмотр и защищённое скачивание доступных договоров;
- заявка клиента на новую аренду;
- заявка на продление действующей аренды;
- выбор способа получения: выдача в офисе или подача по адресу;
- проверка доступности автомобиля с учётом других аренд и ТО;
- передача заявки диспетчеру;
- напоминание сотрудникам и клиенту за день до возврата;
- журналирование значимых действий в Pilot+.

Не входят в первый срез: свободный NLP, голосовые сообщения, распознавание фотографий, расчёт повреждений, реальная оплата и интеграция ГЛОНАСС. Они добавляются после стабильного кнопочного сценария.

## 3. Архитектура

```text
Telegram
    → aiogram-бот на VPS
    → HTTPS + service token
    → Pilot+ Bot API
    → доменные сервисы Pilot+
    → PostgreSQL / private document storage
```

Бот хранит только краткоживущее FSM-состояние диалога в Redis. Постоянные бизнес-данные записывает Pilot+.

VPS запускает Python 3.12+, aiogram 3 и отдельный systemd-сервис. На старте используется long polling, чтобы не требовать публичного webhook до настройки домена и TLS. Позже допускается переход на webhook без изменения бизнес-API.

## 5. Привязка и роли

### Клиент

Сотрудник создаёт в Pilot+ одноразовое приглашение с коротким сроком действия. Клиент открывает Telegram deep link. Backend атомарно погашает приглашение и связывает Telegram user ID с tenant-scoped карточкой клиента. Токен нельзя использовать повторно.

### Сотрудник

Сотрудник получает приглашение от администратора. При каждом значимом действии Pilot+ повторно проверяет активность пользователя, членство в компании и роль. Удаление или блокировка членства немедленно закрывает доступ через бота.

Роли первой версии:

- `CLIENT`: только собственные заявки, аренды и документы;
- `DRIVER`: назначенные операции и автомобили;
- `DISPATCHER`: заявки, выдачи, возвраты и календарь своей компании;
- `ADMIN`/`SUPER_ADMIN`: управление привязками, настройками и уведомлениями в доступном tenant scope.

## 6. Pilot+ Bot API

API размещается в Pilot+ и использует отдельную серверную аутентификацию бота. Каждый запрос содержит service token, Telegram identity и idempotency key для команд записи.

Минимальные операции:

- погасить приглашение и получить безопасный профиль;
- получить доступное меню и capabilities;
- получить собственные аренды клиента;
- получить защищённые ссылки на документы;
- получить доступные автомобили на интервал;
- создать заявку на аренду;
- создать заявку на продление;
- получить назначенные сотруднику операции;
- подтвердить получение уведомления.

Backend не доверяет присланной роли, company ID, client ID, стоимости или доступности автомобиля. Всё повторно определяется по сохранённой Telegram-привязке и текущим данным Pilot+.

## 7. Сценарий новой аренды

1. Клиент нажимает «Новая аренда».
2. Выбирает даты и время.
3. Выбирает конкретную свободную машину либо отправляет запрос диспетчеру, если подходящих машин нет.
4. Выбирает «Выдача в офисе» или «Подача по адресу».
5. Для подачи вводит адрес и контактный комментарий.
6. Бот показывает итог без юридического обещания брони.
7. После подтверждения Pilot+ повторно проверяет аренды и ТО и создаёт заявку идемпотентно.
8. Диспетчер получает уведомление и подтверждает или отклоняет заявку.
9. Только после подтверждения заявка занимает интервал календаря.

Продление проходит через ту же проверку доступности и не изменяет договор молча: Pilot+ сохраняет историю срока и инициатора.

## 8. Напоминания

Планировщик Pilot+, а не процесс Telegram-хендлера, формирует durable notification jobs. Worker бота доставляет их и записывает результат.

Первая версия отправляет:

- клиенту — напоминание о выдаче и возврате;
- рабочей группе — за день до возврата: машина, клиент, телефон, договор и время;
- диспетчеру — новая заявка и запрос продления;
- ответственным — конфликт или приближающееся ТО.

Повторная доставка не создаёт дубликаты благодаря уникальному ключу события. Телефон показывается только ролям с соответствующим правом.

## 9. Ошибки и безопасность

- Секреты находятся только в локальном/server `.env`, не в Git.
- Логи не содержат паспортов, телефонов, Telegram-токена, service token и содержимого договоров.
- API имеет таймаут, ограниченные повторы и безопасные пользовательские сообщения.
- При недоступности Pilot+ бот ничего не записывает локально как завершённую операцию.
- Callback data короткая, типизированная и не содержит PII.
- Документы выдаются через короткоживущую tenant-scoped ссылку Pilot+, а не копируются в файловую систему бота.
- Команды записи используют idempotency key и серверную повторную авторизацию.

## 10. Проверка готовности MVP

- unit-тесты клавиатур, форматтеров и API-клиента;
- тесты FSM новой аренды и продления;
- интеграционные тесты Pilot+ API на tenant boundary, роли, приглашения и идемпотентность;
- сценарий клиент → заявка → диспетчер → подтверждение → календарь;
- сценарий продления с конфликтом;
- сценарий ТО, блокирующий машину;
- сценарий напоминания без повторной доставки;
- запуск бота локально с тестовым токеном;
- systemd health/restart проверка после активации VPS.

## 11. Порядок реализации

1. Контракты Pilot+ Bot API и модели Telegram-привязок/приглашений.
2. Защищённые API-маршруты и тесты tenant boundary.
3. Каркас Python-бота, конфигурация и API-клиент.
4. `keyboards` и `/start` с ролевыми меню.

8. Durable напоминания.
9. Docker/systemd-развёртывание на VPS.
