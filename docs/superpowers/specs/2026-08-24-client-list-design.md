# Список клиентов СУПА ПРО — дизайн

## Цель

Сделать страницу клиентов такой же быстрой и понятной, как новый список договоров: сначала визуальная идентификация клиента, затем главные операционные данные и одно очевидное действие.

## Представление

- На широком экране используется таблица.
- Первая колонка — фотография клиента размером 48–56 пикселей; при отсутствии фото показываются инициалы.
- Далее: ФИО, отдельная колонка телефона, рейтинг, история аренд, машина выбранного договора, стоимость аренды, сумма депозита, отдельный статус депозита, статус клиента и действие «Открыть».
- На узком экране каждая строка превращается в компактную карточку с тем же порядком данных.
- Цвета статусов используют существующие токены дизайн-системы: зелёный для проверенного/постоянного, жёлтый для проверки, красный для заблокированного, нейтральный для черновика и нового клиента.

## Данные

Список получает только реальные tenant-scoped данные:

- число всех аренд клиента;
- число действующих аренд;
- последнюю аренду с датой и автомобилем;
- текущую аренду и автомобиль, если она существует;
- существующий пятизвёздочный рейтинг;
- существующий статус клиента.
- сумму и статус депозита текущей аренды; если текущей аренды нет — депозит последней аренды с пометкой «Последний».
- итоговую стоимость текущей аренды; если текущей аренды нет — стоимость последней аренды.

Статус депозита переводится в операционные подписи: «Не внесён», «У нас», «Возвращён», «Удержан частично» или «Удержан». Если данных нет, интерфейс показывает короткое состояние «Нет аренд», «Сейчас не арендует» или «Нет депозита», без тестовых значений.

Строка договора имеет операционный цвет: зелёный для действующей аренды, синий для полностью закрытой аренды с закрытым депозитом, жёлтый для завершившейся аренды с невозвращённым или неотмеченным депозитом, серый при отсутствии аренды.

## Поиск и фильтры

Сохраняются текущие серверные поиск, фильтры документов, водительского удостоверения и пагинация. Добавляются быстрые ссылки для наиболее частых групп: все клиенты, сейчас арендуют, постоянные, проблемные и заблокированные. Фильтры остаются URL-backed и работают после обновления страницы.

## Компоненты

- Серверный запрос списка расширяется агрегатами аренд и текущей/последней арендой.
- DTO клиента получает отдельный объект краткой истории аренды.
- `ClientGrid` становится адаптивным списком: таблица на desktop, карточки на mobile.
- Фото, звёзды рейтинга и статус переиспользуют существующие компоненты.

## Надёжность и доступность

- Вся строка не становится неявной ссылкой: используется явная кнопка «Открыть».
- Таблица имеет заголовки колонок и доступное имя.
- Фото содержит имя клиента в альтернативном тексте.
- Пустые результаты и отсутствующие сведения отображаются текстом.
- Tenant scope и маскирование телефона/документов сохраняются.

## Проверка

- Серверные тесты проверяют агрегаты аренд и tenant scope.
- Компонентные тесты проверяют порядок фото и данных, статусы, рейтинг, пустые значения и мобильную разметку.
- Страница проверяется на реальных локальных данных в браузере.
