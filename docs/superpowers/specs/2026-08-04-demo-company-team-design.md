# Pilot+ Demo Company and Team Design

**Статус:** реализован и проверен 4 августа 2026 года; локальная миграция применена,
идемпотентный seed и браузерные сценарии пройдены.

## Цель

Добавить в Pilot+ один реалистичный демонстрационный профиль компании и по одному неактивному пользователю каждой корпоративной роли. Данные хранятся в PostgreSQL, повторяемо создаются через seed и отображаются в существующем центре управления `/admin`.

## Объём

В этап входят:

- реквизиты одной demo-компании;
- четыре неактивных профиля команды;
- привязка профилей к компании через существующие роли;
- отображение компании и команды в `/admin`;
- миграция Prisma, идемпотентный seed и тесты.

Не входят:

- вход под demo-профилями;
- создание временных паролей;
- формы создания и редактирования;
- приглашения, документы, фотографии и удаление пользователей;
- изменение системной роли Павла Седова.

## Модель данных

`Company` расширяется nullable-полями, чтобы миграция не ломала существующие компании:

- `inn`, `kpp`, `ogrn`;
- `directorName`;
- `legalAddress`, `actualAddress`;
- `phone`, `email`;
- `isDemo` с default `false`.

Для demo-компании seed заполняет все поля. ИНН, КПП и ОГРН хранятся строками, чтобы не терять ведущие нули и не выполнять арифметические операции.

## Интерфейс `/admin`

Существующие KPI и быстрые действия сохраняются. Ниже них добавляются два серверных блока:

1. «Компания» — название, demo-статус, ИНН, КПП, ОГРН, директор, адреса и контакты.
2. «Команда» — адаптивный список из четырёх профилей с аватаром-инициалами, именем, email, русским названием роли и статусом «Неактивен».

SYSTEM scope видит demo-компанию и её команду. COMPANY scope получает только компании из `access.companyIds`; запрос не загружает пользователей чужих компаний. Парольные hash и дополнительные разрешения не входят в DTO.

Если реквизитов или команды нет, используются компактные empty states без неработающих кнопок.

## Seed и безопасность

Seed использует `upsert` по существующим уникальным ключам компании, пользователя и членства. Повторный запуск обновляет demo-данные и не создаёт дубликаты.

Неактивность проверяется существующим auth-layer. Seed и UI никогда не выводят технические hash, session tokens или значения `.env`.

## Проверка

- schema/migration tests для новых полей;
- seed tests для компании, четырёх пользователей, ролей и повторяемости;
- query tests для SYSTEM и COMPANY scope;
- component tests для реквизитов, ролей и empty states;
- browser test desktop/mobile без горизонтального переполнения;
- typecheck, unit regression и production build.
