# Material-inspired UI: обратимый первый этап

## Согласованное направление

Собственная адаптация Materialize на текущих React, Tailwind и семантических токенах СУПА ПРО. Не переносить платные исходники шаблона и не устанавливать MUI ради смены оформления. Сохранить основной синий цвет и светлую/тёмную темы.

## Первый законченный этап

- Добавить отдельный режим интерфейса Material в существующий переключатель. Существующие classic и obsidian сохранить без изменения внешнего вида.
- Подготовить кнопки, поля, select, checkbox, переключатели, бейджи, карточки и диалоги в общей библиотеке и показать в существующем UI-kit.
- Применить новый режим к форме новой аренды: логические секции, ясные подписи, ошибки рядом с полями, фиксированная последовательность шагов, понятное состояние сохранения.
- Использовать единый набор иконок из уже установленной библиотеки. Не менять смысл действий.
- Сохранить текущие серверные проверки, tenant-доступ, имена полей, отправку и расчёты. Не добавлять новые запросы или изменения базы ради оформления.

## Следующие самостоятельные этапы

Графики на реальных данных и справочник API выполняются после первого этапа. Для API сначала инвентаризировать реально существующие маршруты, авторизацию и ограничения. Не публиковать внутренние секреты и не выдавать Server Actions за публичное API.

## Возврат

Архив исходников до работ: backups/pre-materialize-ui-20260923.tar.gz. Включает src, public, package.json, lockfile и конфигурацию Next/TypeScript; не является резервной копией базы или секретов.

На сервере исходная точка до редизайна: /opt/pilot-plus/releases/20260922-header-right (перед публикацией перепроверить current). Новый релиз собирать отдельно; предыдущий не удалять. При проблемах запуска вернуть симлинк предыдущего релиза. Для обычного возврата внешнего вида достаточно выбрать прежний режим в профиле.

## Проверка

Unit-тесты переключения режима и формы, существующие тесты аренды, ESLint, TypeScript и production build. В браузере проверить 390px и desktop, обе темы, клавиатуру, фокус диалогов, ошибки и незаполненные поля. Проверку создания договора выполнять только в безопасной тестовой среде.

## Критерий завершения

Пользователь может выбрать новый режим и вернуть прежний; форма аренды работает с неизменным серверным контрактом. Отдельно перечислить выполненные изменения, проверки и ещё не реализованные этапы.
