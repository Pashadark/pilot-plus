# Pilot+

Pilot+ — веб-платформа для управления коммерческим автопарком и транспортной телематикой. Создатель и владелец проекта — **Павел Седов (Pashadark)**.

Сейчас репозиторий содержит интерактивный dashboard, безопасный вход администратора, автопарк из PostgreSQL, личный профиль и локальную инфраструктуру. Главная страница показывает карту и оперативное состояние демонстрационного парка, `/vehicles` содержит 130 импортированных автомобилей, `/profile` позволяет администратору управлять учётной записью, `/system` показывает доступность инфраструктуры, `/ui-kit` документирует дизайн-систему, а `/login` выполняет серверную авторизацию. API телеметрии, приём MQTT и real-time обновления ещё не реализованы.

## Маршруты

- `/` — адаптивный центр управления транспортом. На телефоне карта занимает полноэкранное рабочее пространство с поиском, фильтрами и нижней панелью; начиная с `md` используется настольная оболочка, где карта остаётся крупнейшей областью.
- `/vehicles` — автопарк текущей компании с поиском, фильтрами, адаптивными карточками и данными из PostgreSQL.
- `/vehicles/[id]` — подробная карточка автомобиля с обзором, поездками, маршрутами, событиями, топливом, обслуживанием и документами.
- `/profile` — защищённый профиль администратора: изменение имени и email с подтверждением текущим паролем, а также смена пароля с завершением остальных сессий.
- `/system` — защищённая диагностическая страница доступности PostgreSQL, Redis и MQTT. Она показывает только статус, задержку и время проверки, не раскрывая адреса сервисов и значения переменных окружения.
- `/ui-kit` — исполняемая витрина компонентов, состояний, токенов и правил применения дизайн-системы Pilot+.
- `/login` — публичная форма входа администратора. Остальные маршруты требуют действующую серверную сессию.

Карта построена на MapLibre GL и демонстрационных координатах. Тайлы и атрибуция OpenStreetMap подходят для прототипа; production-провайдер, SLA, лимиты и условия использования ещё должны быть выбраны.

Страница `/system` — прикладная диагностика, а не production-мониторинг: в development для Redis и MQTT используются безопасные локальные значения по умолчанию `127.0.0.1:6379` и `127.0.0.1:1883`; вне development адрес и порт нужно задавать явно. Она не заменяет метрики, алерты, логи и внешний uptime-monitoring.

## Фактический стек

- Next.js 16.2 App Router, React 19.2, TypeScript 5;
- Tailwind CSS 4 и семантические CSS-переменные;
- MapLibre GL, Framer Motion, React Icons;
- Prisma 6.16, серверные сессии PostgreSQL и Node.js `scrypt`;
- Sharp для приведения разрешённых исходных фотографий к локальному WebP;
- PostgreSQL/PostGIS, Redis и Mosquitto в Docker Compose;
- Vitest, Playwright, ESLint и Prettier для контроля качества.

## Быстрый запуск

Требуются Node.js 20+, npm и, для инфраструктуры, Docker Desktop.

```powershell
npm install
docker compose up -d
npm run db:preflight:maintenance
npx prisma migrate deploy
npm run db:seed
npm run dev
```

`db:preflight:maintenance` выполняет только чтение и обязан запускаться непосредственно перед
`prisma migrate deploy`. Он останавливает обновление, если legacy-статусы ТО нельзя безопасно
сопоставить или нормализовать; сначала исправьте данные вручную и проверьте резервную копию.

Перед seed скопируйте `.env.example` в `.env` и задайте собственные `PILOT_ADMIN_EMAIL`, `PILOT_ADMIN_PASSWORD` (минимум 12 символов) и `PILOT_ADMIN_NAME`. Для явной проверки Redis и MQTT на `/system` используйте `REDIS_HOST`, `REDIS_PORT`, `MQTT_HOST` и `MQTT_PORT`; в production все четыре переменные должны быть заданы. `.env` нельзя добавлять в Git или выводить в логи.

Приложение доступно по адресу <http://localhost:3000>. PostgreSQL/PostGIS слушает `127.0.0.1:5433`, Redis — `127.0.0.1:6379`, MQTT — `127.0.0.1:1883`, MQTT WebSocket — `127.0.0.1:9001`.

## Правила интерфейса и данных

Компоненты используют семантические токены (`--color-surface`, `--color-text`, `--color-primary` и другие), а не локальные hex-цвета. Светлая и тёмная темы меняют значения токенов на корневом элементе; режим уменьшенного движения отключает обычные переходы. Навигация и действия доступны с клавиатуры, а публичные области касания имеют размер не меньше 44×44 пикселей.

Визуальная система интерфейса использует светлую плотную композицию в стиле Mosaic: компактную навигационную рейку, фиолетовый акцент и плоские информационные панели; продуктовые сценарии и карта остаются собственными Pilot+.

Дашборд и карта пока используют типизированные **fixtures**. Раздел `/vehicles` читает из PostgreSQL 130 импортированных карточек, принадлежащих компании администратора. Характеристики и стоимость взяты из предоставленного каталога; координаты, пробег, топливо, поездки и события не выдумываются и показывают состояние «Нет данных», пока не подключена реальная телеметрия.

Карточки и профиль автомобиля используют 130 локальных WebP-фотографий с разрешённого источника `autopilotrent.ru`. Обычный `npm run db:seed` читает версионируемый манифест и не обращается к сети. Команду `npm run vehicles:sync-images` следует запускать явно только при обновлении исходного каталога: она читает официальный публичный API, проверяет полное сопоставление, скачивает или преобразует файлы и повторно использует уже существующие изображения.

Защищённое приложение использует глобальные тосты четырёх типов: успех, предупреждение, ошибка и информация. На телефоне уведомления занимают доступную ширину, а на компьютере закреплены справа сверху.

## Ошибки и границы маршрутов

Для неизвестного пути используется фирменная 404-страница; для неизвестного автомобиля — локальная 404 в разделе транспорта. Глобальная, защищённая и транспортная error boundary показывают понятный русский текст и кнопку «Повторить» через `unstable_retry` Next.js 16.2. Пользователю нельзя показывать `error.message`, стек или конфигурацию: при наличии отображается только безопасный `digest` как код обращения.

## Что ещё в roadmap

В проекте пока одна роль `ADMIN`; полноценная RBAC-модель, PWA, production-мониторинг с алертами и observability, а также приём телеметрии и real-time канал остаются будущими этапами. Диагностика `/system` не означает, что эти production-возможности уже готовы.
